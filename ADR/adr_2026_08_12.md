# Architectural Decision Records — 2026-08-12

## Consume live corner context from co-driver over the existing WebSocket

**Status:** Superseded by [ADR 2026-08-27](adr_2026_08_27.md), which removed the co-driver WebSocket path.

### Context

The Driver Coach HUD needs to identify the current or next track corner and its
phase. The telemetry stream contains the raw driving inputs, but the track
corner template and distance matcher belong to the independent `co-driver`
project.

### Decision

- `co-driver` remains the owner of corner geometry, template loading, matching,
  and corner phase calculation.
- The HUD consumes `corner_template` and `corner_state` messages through the
  selected local WebSocket: `3000` for production and `3001` for development.
- The HUD does not read the co-driver database, call its HTTP API, or recreate
  corner detection from raw telemetry.
- Corner messages are treated as render state: the HUD keeps only the latest
  template and latest state, clears them on reconnect/session reset, and updates
  the DOM through the existing animation-frame render cycle.

### Consequences

- The two repositories keep clear ownership boundaries and can evolve the
  corner matcher independently from HUD presentation.
- The HUD must handle loading, unavailable, inactive, and context-mismatch
  states without showing stale corner numbers.
- A coordinated WebSocket contract change is required if corner message fields
  or semantics change.

## Select the co-driver channel by build

**Status:** Superseded by [ADR 2026-08-27](adr_2026_08_27.md), which removed the co-driver WebSocket path.

### Context

`co-driver` separates production and development/lab runtime channels. The HUD
must connect to the matching WebSocket so development telemetry cannot be read
from production or accidentally write test recordings to the production
channel.

### Decision

- Production HUD builds connect to `ws://127.0.0.1:3000/_ws`.
- `develop` HUD builds connect to `ws://127.0.0.1:3001/_ws`.
- Browser previews select development explicitly with `?channel=develop`.
- The HUD never probes both ports or falls back automatically.

### Consequences

- The Tauri `develop` profile adds `channel=develop` to its local page before
  the overlay opens its WebSocket.
- Tauri CSP allows both local WebSocket endpoints, while the runtime selects
  exactly one.
- The co-driver repository remains the owner of the port and telemetry channel
  configuration.
