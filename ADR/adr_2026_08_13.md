# ADR 2026-08-13: Full-screen transparent HUD with movable Coach card

## Status

Accepted for the Driver Coach MVP.

## Context

The original Tauri window was only large enough for a compact HUD near the
bottom of the screen. The Driver Coach needs to be readable at a glance and
must be placeable at the driver's preferred sight line. The HUD must continue
to consume only the existing co-driver WebSocket messages and must remain
transparent, always-on-top, focusless, and click-through during normal driving.

## Decision

The Tauri window is resized to the primary monitor and positioned at that
monitor's origin. The browser layer keeps the telemetry HUD anchored near the
bottom and renders the Coach as an independently positioned card.

Normal mode keeps the entire window click-through. A system-tray menu enters a
temporary edit mode; the Rust layer enables focus and pointer events, while
the browser layer provides drag bounds, a reset action, and localStorage
persistence. Pressing `DONE`, `Escape`, or `Exit edit mode` restores focusless
click-through behavior.

## Consequences

- Coach placement does not require a WebSocket, protocol, database, or co-driver
  change.
- The saved position is local to the HUD machine and is clamped to the current
  primary monitor.
- The MVP edits the primary monitor only; multi-monitor placement is deferred.
- The tray icon becomes part of the desktop interaction model for the HUD.

## Reference Coach boundary

The HUD consumes an optional `coach_reference` WebSocket message. Its payload
contains an explicit `available` flag, corner context, phase, one cue or a list
of cues, and an optional post-corner summary. The HUD selects and formats the
highest-priority cue, but does not calculate an ideal braking point or infer a
quality judgment from raw telemetry.

When reference data is unavailable, the HUD falls back to the existing corner
readout and observed Driver Coach phase. This prevents unsupported advice from
appearing during unknown-track or first-lap driving. The producer and exact
field mapping remain a coordinated co-driver integration concern; this
repository only implements the consumer and demo contract.
