# ADR 2026-09-25: Public repository and release workflow

## Separate development and release branches

**Status:** Accepted.

### Context
- FDC is about to be distributed publicly, so users need builds that change only at deliberate releases.
- Committing every change directly to `main` makes every intermediate state look like released source.

### Decision
- `develop` is the working branch; each logically complete and locally verified change is committed and pushed to `origin/develop`.
- `main` is the release branch and stays the GitHub default branch. It changes only by fast-forwarding to `develop` during a release that the owner explicitly requests.
- When `develop` has no version bump since the latest release, the owner may fast-forward `main` without a tag to publish documentation, tests, or CI changes.
- Fixes go through `develop` like any other change; there are no hotfix commits on `main`.
- All builds use the standard Cargo `release` profile; there is no separate `develop` Cargo profile.

### Consequences
- Repository visitors see the released source and documentation by default.
- `main` and `develop` never carry diverging versions, so a release is always a fast-forward.
- Several `develop` changes can accumulate before one release.

## Tag only published releases

**Status:** Accepted.

### Context
- The previous rule created an annotated tag for every version bump, which would publish many versions that never ship as releases.

### Decision
- Version bumps follow the existing impact rules and happen on `develop` for each change; no tags are created on `develop`.
- An annotated tag `vX.Y.Z` is created on `main` only at a release.
- The Release workflow validates the tag against `src-tauri/Cargo.toml` and `main`, builds the NSIS installer, attaches SHA-256 files, and creates a draft GitHub release that the owner completes and publishes.
- Installers remain unsigned until Authenticode signing is adopted.

### Consequences
- Users see version jumps between releases, for example `v7.16.46` to `v8.18.49`; intermediate versions remain visible in the `src-tauri/Cargo.toml` history.
- Existing per-bump tags up to `v7.16.46` remain as history.

## Publish the repository

**Status:** Accepted.

### Context
- FDC is MIT-licensed and was developed in a private repository.

### Decision
- Prepare the repository to become public, with the change of visibility as a separate final step.
- Keep decision records in the repository as history, each entry marked with its current status.
- Never commit personal data, absolute user paths, credentials, signing material, telemetry captures, or databases; CI enforces the file-type and path checks.

### Consequences
- Anyone can inspect, fork, and build FDC from source.
- Superseded decisions stay readable with a status that points to the decision replacing them.
