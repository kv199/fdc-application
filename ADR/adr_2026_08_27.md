# ADR 2026-08-27: Make Direct Data Out the only FDC runtime flow

## 19:16 - Remove the co-driver runtime dependency

### Context
- FDC was extracted from the Suite but still carried a selectable Suite/WebSocket telemetry path, a port-3001 probe, provider-owned reference messages, and related Configuration and documentation surfaces.
- The standalone product needs one predictable local-first flow from Forza Horizon 6 Data Out through FDC to the HUD, recording, and analysis paths.

### Decision
- FDC always binds `127.0.0.1:5301` and sends valid FH6 packets through the normalized `queueTelemetry` pipeline.
- Remove Suite/WebSocket source selection, reconnect lifecycle, probe, CSP WebSocket allowance, provider reference/corner message consumers, and their user-facing contract documentation.
- Keep Asphalt Coach, Shift Light, lap timing, recording, and analysis local to the Direct Data Out flow.
- Configuration reports only Direct Data Out startup, packet availability, stale data, and incompatible packet-format states.

### Consequences
- FDC no longer requires Suite, co-driver, Docker, or a WebSocket endpoint at runtime.
- Historical Suite/WebSocket ADRs remain as superseded architectural history; active product documentation describes only the Direct Data Out contract.
- Reference-track and provider-owned corner guidance are no longer available in the standalone HUD; local current-run analysis remains supported.
